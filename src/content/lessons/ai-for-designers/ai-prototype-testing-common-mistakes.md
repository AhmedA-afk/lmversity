This page matters as a pre-registration check: run your evaluation plan against these four traps before you run a single session. Each trap is cheap to prevent and expensive to discover afterward.

## 1. Cherry-picked prompts

Testing only the inputs your design handles well. The symptom is a scenario set drawn from the designer's imagination after the design is done. The fix is the [four-bucket set](/learn/ai-for-designers/creating-a-realistic-ai-test-set) — representative, difficult, sensitive, known failures — with scenarios dated and sourced, plus unseen examples in every evaluation round.

## 2. Demo-only flows

Prototyping the golden path and calling unbuilt states "out of scope for testing." If blocked, failed, cancelled, and corrected states are not in the prototype, the evaluation cannot speak about the experience that ships. The fix: the prototype covers at least five states with labeled exits — the [state model](/learn/ai-for-designers/ai-feature-state-model-worked-example) names the full set — and unbuilt branches are marked unbuilt rather than faked.

## 3. Changing criteria mid-round

Moving the goalposts between sessions — scoring usefulness one week and delight the next, or letting the loudest stakeholder redefine "good" after seeing results. The fix is the written [rubric](/learn/ai-for-designers/designing-a-ux-evaluation-rubric) with six fixed criteria, independent scoring before discussion, and disagreements kept as data rather than smoothed over.

## 4. Missing baselines

Reporting prototype scores with nothing to compare against. Is a given score good? Compared to what — the hand-written workflow, the macro-based alternative, the previous iteration? The fix: score the non-AI baseline — [choosing where AI belongs](/learn/ai-for-designers/choosing-where-ai-belongs-worked-example) shows how to state one — on the same rubric where comparable, and always re-run the same set after revisions so change is measured, not asserted.

## How to use this list

Attach it to your findings log as a signed checklist: set built from four buckets, states covered, rubric fixed before the round, baseline scored. A log that cannot check all four is a draft, not evidence — and evidence is what the capstone requires.
