## The short answer

AI works in many languages, but not equally well — quality tends to track how much text the model saw in that language. And it is genuinely useful as an accessibility tool: describing images, simplifying dense text, restructuring documents for screen readers. Both cases run on the same rule you already know: the output is a draft, and someone verifies it.

## Why this matters

Two people can type the same question into the same tool and get noticeably different quality — one in English, one in a lower-resource language. The second person is not doing anything wrong; the model's knowledge is unevenly distributed. Knowing that changes how you verify.

On the accessibility side, AI removes friction that used to need another person or expensive software — but only if the output is checked, because a plausible-sounding wrong description is worse than none.

## Working in your own language

Three patterns, in order of reliability:

1. **Work in-language when the content is in-language.** Asking about a Hindi document in Hindi keeps names, terms, and nuance intact. If the answer reads like it was thought in English and translated, it probably was — re-ask and say so.
2. **Bridge through English for technical topics.** When the subject is code, science, or anything documented mostly in English, asking in English and then translating the *answer* often works better — but keep names and technical terms in the original language and check them separately.
3. **Ask for locale, not just language.** "Answer in Tamil" gets you language. "Answer for a reader in Tamil Nadu" gets you locally relevant units, examples, and conventions. Dates, currency, forms of address, and idioms are where translated-sounding answers break first.

The check that always applies: if the answer contains a fact you will rely on — a date, a figure, a name, a rule — verify it in-language, not through the same tool that produced it.

## AI as an accessibility assistant

Where it earns its place:

- **Alt text and image descriptions.** Paste or upload an image, ask for a description, then edit it yourself — you know which details matter for *your* document. AI drafts; you decide what the reader needs.
- **Reading-level simplification.** "Rewrite this for a tired reader" or "at a lower reading level" is a real accessibility feature — dense official documents become navigable. Facts must survive the rewrite; check the important ones.
- **Screen-reader-friendly structure.** Ask for proper headings, short paragraphs, and real lists instead of visual formatting. A document that reads well as pure text reads well for everyone.
- **Transcription and captioning drafts.** Speech-to-text plus a summarizing pass turns meetings and lectures into notes — with the usual caveat that names and numbers need a human ear.

## The shared verification rule

Both cases — other languages, accessibility — have the same failure shape: output that is fluent, helpful-sounding, and wrong in a way the format hides. Fluency is not evidence. The habits in [the verification checklist](/learn/ai-literacy/the-verification-checklist) were built for exactly this.
