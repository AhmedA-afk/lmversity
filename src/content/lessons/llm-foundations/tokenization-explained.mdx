Before a language model can do anything with your text, it has to turn it into numbers. That conversion is **tokenization**, and it happens in two stages: split the text into tokens, then map each token to an integer ID the model can look up.

## Tokens are subwords, not words

A token is usually a chunk of a word, not a whole word. Common words are often a single token; rarer words get split. "Tokenization" might break into `token` + `ization`, and an unusual name might split into three or four pieces. Whitespace and punctuation get their own tokens too.

The rulebook for how to split is learned once, ahead of time, by an algorithm like **Byte-Pair Encoding (BPE)**: start from individual characters and repeatedly merge the most frequent adjacent pair into a new token, until you reach a fixed vocabulary size (commonly 50k–200k tokens).

## Why you should care

This isn't trivia — token boundaries explain a lot of everyday behaviour:

<Callout kind="production" title="Cost and limits are counted in tokens, not words">
Cost and limits are counted in tokens, not words (roughly 4 characters per token in English). See [Tokens, Context, and Cost](/learn/ai-foundations/tokens-context-cost). Other languages can cost more: text in languages under-represented in training tends to split into more tokens, so the same sentence can cost several times as much.
</Callout>

<Callout kind="breaks" title="Spelling and counting are hard because of tokens">
Because the model sees `straw` + `berry` rather than the letters, "how many r's are in strawberry?" is genuinely awkward for it.
</Callout>

## Every token becomes an ID

After splitting, each token maps to an integer, and that integer indexes into the model's embedding table — the bridge from text to the geometry the network actually computes on. From there the model does its one job: [next-token prediction](/learn/llm-foundations/next-token-prediction).
