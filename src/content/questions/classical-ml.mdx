## 1. What is feature engineering, and why does it still matter?

Turning raw data into inputs a model can learn from — encodings, aggregations, ratios, domain signals. It still matters because classical models (trees, linear models) can only learn what the features express; the model is often less important than whether the features carry the signal. Deep learning moved feature work inside the model, it didn't eliminate it.

**Follow-up:** give an example where the feature mattered more than the model choice.

## 2. Explain the bias-variance tradeoff.

Bias is error from a model too simple to capture the pattern — it underfits. Variance is error from a model too sensitive to the training sample — it overfits. You trade one against the other: complexity lowers bias and raises variance. The engineering version: total error is what matters, and the sweet spot is found by validation, not theory.

**Follow-up:** how does adding more training data shift each side?

## 3. Why is a random train/test split sometimes wrong?

When the data has structure the split must respect: time (train on past, test on future — random leaks tomorrow into training), groups (same user's rows in both splits leak identity), and deduplication (near-duplicate rows across the split inflate metrics). The split has to model *how the model will be used*, not just sample rows.

**Follow-up:** what's the failure called when future information leaks into training, and why is it so dangerous?

## 4. What is data leakage?

Information that wouldn't exist at prediction time sneaking into features or evaluation. The classic cases: a feature derived from the outcome, the same entity in train and test, preprocessing fit on the whole dataset before splitting. It's dangerous because the model looks great in eval and collapses in production — the leak was doing the work.

**Follow-up:** a feature seems harmless but correlates perfectly with the label — what do you check?

## 5. Explain gradient descent in one minute.

The loss function measures wrongness; its gradient points uphill. Gradient descent steps downhill — compute the gradient on the data, nudge the parameters opposite, repeat. Learning rate controls step size: too big and it overshoots, too small and it crawls. Everything else — momentum, Adam, schedules — is a refinement on that loop.

**Follow-up:** what's the difference between batch, mini-batch, and stochastic descent in practice?

## 6. When does a simple model beat a complex one?

When data is limited, features are strong, interpretability is required, or the problem is roughly linear. A tuned logistic regression on good features often beats a neural net on the same data — and it debugs, explains, and deploys easier. The decision isn't sophistication; it's where the marginal accuracy lives relative to the operational cost.

**Follow-up:** name a production setting where you'd choose the simpler model even at slightly lower accuracy.

## 7. Debug this: validation accuracy is 94% but production is 71%. Where do you look?

**Format: debug this output.**

Look for the distribution gap first — the three usual suspects: leakage inflating validation, a split that didn't match production structure (time, group, dedup), or label problems (validation labels were easy/gold; production labels are noisy). Then check serving skew — features computed differently in production than in training. The metric didn't lie; it measured a different dataset than the one you shipped to.

**Follow-up:** which check do you run first, and what would it cost to be wrong?

## How to score your answers

- **Strong answers** treat evaluation as the hard part — splits, leakage, and production-skew dominate real failures more than model choice.
- **Weak answers** reach for "more data" or "bigger model" before diagnosing which error is actually present.
- Follow-ups push on *what you check first* — the debugging order reveals real experience.
